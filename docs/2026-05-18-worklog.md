## 2. 테마 토글 Hydration 오류 수정

### 증상
About 페이지 진입 시 콘솔 에러:
```
Error: Hydration failed because the initial UI does not match what was rendered on the server.
Expected server HTML to contain a matching <circle> in <svg>.
```

### 원인 분석
- `Header.tsx`의 테마 토글 버튼이 `useTheme()`의 `theme` 값으로 `<Sun>` / `<Moon>` 아이콘을 조건부 렌더링
- `next-themes`의 `useTheme()`는 **서버 사이드에서 `theme === undefined`** 를 반환
- 결과:
  - 서버 렌더링: `undefined === 'dark'` → `false` → `<Moon>` (circle 없음)
  - 클라이언트: `'dark'` 확정 후 `<Sun>` (circle 있음)
  - → SVG 구조 불일치로 hydration mismatch

### 해결
`mounted` 패턴으로 클라이언트 마운트 이후에만 아이콘 렌더링.

```tsx
const { resolvedTheme, setTheme } = useTheme();
const [mounted, setMounted] = useState(false);

useEffect(() => setMounted(true), []);

// ...
{mounted && (resolvedTheme === 'dark' ? <Sun /> : <Moon />)}
```

추가로 `theme` 대신 `resolvedTheme` 사용 — `system` 테마일 때도 안전.

## 3. Grafana Cloud + Alloy 모니터링 구성 (메인 작업)

### 3.1 아키텍처 결정

| 옵션 | 선택 여부 | 이유 |
|------|-----------|------|
| EC2에 Prometheus + Grafana 풀 스택 | ❌ | t3.micro 1GB RAM 한계 |
| t3.small로 업그레이드 후 풀 스택 | ❌ | 월 ~$7 비용 추가 |
| **Grafana Cloud + 경량 Alloy 에이전트** | ✅ | 무료, 메모리 부담 최소 |

**구성:**
```
NestJS API (/metrics)
        ↓ scrape (internal network)
Grafana Alloy (~50MB on EC2)
        ↓ remote_write (edge network)
Grafana Cloud (Tokyo region)
```

### 3.2 Grafana Cloud 발급 정보
- Region: Japan (Tokyo) — 한국에서 가장 가까운 리전
- Remote Write URL: `https://prometheus-prod-49-prod-ap-northeast-0.grafana.net/api/prom/push`
- Username (Instance ID): `3222724`
- API Token: 별도 보관 (채팅 노출 토큰은 폐기)

### 3.3 NestJS Prometheus 설정

```bash
npm install @willsoto/nestjs-prometheus prom-client -w @portfolio/api
```

```ts
// app.module.ts
imports: [
  PrometheusModule.register({
    path: '/metrics',
    defaultMetrics: { enabled: true },
  }),
  // ...
]

// main.ts
app.setGlobalPrefix('api', { exclude: ['metrics'] });
// → /metrics 경로가 글로벌 prefix(/api)에서 제외됨
```

### 3.4 Alloy 설정 (`docker/alloy/config.alloy`)

```alloy
prometheus.scrape "nestjs_api" {
  targets = [{ __address__ = "api:4000" }]
  metrics_path    = "/metrics"
  scrape_interval = "15s"
  forward_to      = [prometheus.remote_write.grafana_cloud.receiver]
}

prometheus.remote_write "grafana_cloud" {
  endpoint {
    url = env("GRAFANA_REMOTE_WRITE_URL")
    basic_auth {
      username = env("GRAFANA_USERNAME")
      password = env("GRAFANA_API_TOKEN")
    }
  }
}
```

## 4. 마주친 이슈들

### 이슈 1. Alloy 컨테이너 DNS 조회 실패

**증상:**
```
err="Post \"https://prometheus-prod-49-prod-ap-northeast-0.grafana.net/api/prom/push\":
dial tcp: lookup prometheus-prod-49-prod-ap-northeast-0.grafana.net on 127.0.0.11:53: server misbehaving"
```

**원인:**
- `compose.prod.yml`의 `internal` 네트워크는 `internal: true` 설정으로 외부 인터넷 차단
- alloy가 internal에만 연결되어 있어 Grafana Cloud 호스트명 해석 불가

**해결:**
alloy 서비스에 `edge` 네트워크 추가 — internal은 api 접근용, edge는 외부 전송용.

```yaml
alloy:
  networks:
    - internal   # api:4000 접근
    - edge       # Grafana Cloud 전송
```

### 이슈 2. VPS PEM 파일로 SSH 접속 실패

**증상:**
```
ssh -i "Croco_portfolio.pem" ec2-user@54.116.63.99
ec2-user@54.116.63.99: Permission denied (publickey).
```

**원인:**
- 서버 OS가 Ubuntu 22.04 LTS → 기본 사용자는 `ubuntu`, `ec2-user`가 아님

**해결:**
```bash
ssh -i "Croco_portfolio.pem" ubuntu@54.116.63.99
```

> DEPLOYMENT.md에 이미 명시되어 있던 정보 — 문서 먼저 봤어야 함.

### 이슈 3. GHCR 이미지 pull denied

**증상:**
```
docker compose -f compose.prod.yml pull
✘ Image ghcr.io/cr0c0-mj/portfolio-web:latest Error error from registry: denied
```

**원인:**
- VPS의 Docker가 GHCR에 로그인되어 있지 않음
- GHCR은 GitHub PAT(`read:packages` 권한) 필요

**해결:**
```bash
echo "[PAT]" | docker login ghcr.io -u Cr0c0-MJ --password-stdin
```
로그인 정보는 `~/.docker/config.json`에 저장되므로 1회만 실행.

### 이슈 4. GitHub Actions `git pull` 인증 실패

**증상:**
```
remote: Invalid username or token. Password authentication is not supported for Git operations.
fatal: Authentication failed for 'https://github.com/Cr0c0-MJ/portfolio.git/'
```

**원인:**
- `appleboy/ssh-action`은 비대화형 셸로 접속 → git credential helper 미작동
- 사용자가 수동으로 `git remote set-url`로 PAT를 박아두어도, Actions 환경에선 인식 불가
- `deploy.yml`의 `git pull --ff-only`는 stored credential을 기대하지만 없음

**해결:**
워크플로우에서 PAT를 URL에 직접 주입.
```yaml
git pull https://Cr0c0-MJ:${{ secrets.VPS_GIT_PAT }}@github.com/Cr0c0-MJ/portfolio.git --ff-only
```

### 이슈 5. GitHub 시크릿 이름 예약어 충돌 (실수 사례)

**증상:**
- 시크릿 이름을 `GITHUB_PAT`으로 등록하려 했으나 **저장 버튼이 비활성/오류**

**원인:**
- **`GITHUB_*` prefix는 GitHub Actions 예약어** — 시크릿 이름으로 사용 불가
- 같은 이유로 `GITHUB_TOKEN`은 자동 주입되는 빌트인 토큰

**해결:**
이름을 `VPS_GIT_PAT`으로 변경, `deploy.yml`도 그에 맞춰 수정.

---

### 이슈 6. "Re-run failed jobs"가 새 워크플로우를 안 씀

**증상:**
- `deploy.yml` 수정 후 main에 머지했는데도 재실행 시 동일 오류

**원인:**
- **"Re-run failed jobs"** 는 원래 트리거된 커밋의 워크플로우 파일을 그대로 재사용
- 새 워크플로우 파일 적용하려면 **새 실행**을 트리거해야 함

**해결:**
GitHub Actions → 워크플로우 → 우상단 **"Run workflow"** 버튼 (workflow_dispatch) 사용.
